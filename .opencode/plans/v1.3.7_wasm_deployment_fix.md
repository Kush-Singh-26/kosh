# Plan: Fix WASM Deployment (v1.3.7)

This plan addresses the final edge case causing the `msgpack: invalid code=a1 decoding int64` error when running `kosh build` outside the Kosh source tree.

## 1. Problem Analysis
The root cause of the error is that Kosh is failing to extract and deploy the newly updated embedded WASM binary to the user's `static/wasm/` directory when running as an installed executable.

In `builder/run/builder.go`, the `checkWasmUpdate` function attempts to hash the Kosh source directories (like `cmd/search`) to see if the WASM needs rebuilding. When running in a normal user's project, these source directories do not exist. `utils.HashDirsFast` throws an `os.ErrNotExist` error, which causes Kosh to log a warning and return early, **completely bypassing the WASM extraction logic (`build.CheckWASM`)**.

This means users are left with their old cached `search.wasm` on disk, which crashes when it tries to decode the new `search.bin` string keys.

## 2. Proposed Solution
We need to clearly separate Kosh's "Internal Developer Mode" (compiling WASM from source on the fly) from "Production Mode" (extracting the embedded WASM). 

If Kosh detects it is not running inside its own source tree, it should immediately skip all source-hashing logic and just call `build.CheckWASM("")` to ensure the embedded binary is extracted if needed.

## 3. Implementation Steps

### 3.1 Update `builder/run/builder.go`
Modify `checkWasmUpdate` to explicitly check for `inSourceTree` at the very beginning of the function:

```go
func (b *Builder) checkWasmUpdate() {
	wasmSrcDirs := []string{
		"cmd/search",
		"builder/search",
		"builder/models",
	}

	// Detect if we are in the source tree
	inSourceTree := false
	if _, err := os.Stat(filepath.Join("cmd", "search", "main.go")); err == nil {
		inSourceTree = true
	}

	// If running outside the Kosh repository (e.g. in a user's site), 
	// bypass source hashing and directly deploy the embedded WASM.
	if !inSourceTree {
		build.CheckWASM("")
		return
	}
    // ... rest of the developer-mode logic
```

### 3.2 Verify Extraction
Once implemented, running `kosh build` outside the source tree will trigger the `CheckWASM` hash comparison and successfully extract the updated `search.wasm`.
