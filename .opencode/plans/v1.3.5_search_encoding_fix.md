# Plan: Search Encoding Robustness (v1.3.5)

This plan addresses the `msgpack: invalid code=91 decoding int64` error during search initialization in the browser. The error indicates a type mismatch during MessagePack decoding, likely caused by `map[int]` usage which can be inconsistent between 64-bit Windows (encoding) and 32-bit WASM (decoding).

## 1. Problem Analysis
The MessagePack error `0x91` corresponds to an array of length 1. When the decoder expects an `int64` (for a map key or integer field) but finds an array, it throws this error. This often happens with `map[int]` types when the library gets misaligned across different architectures.

## 2. Proposed Solution
Switch all search-related maps to use `string` keys. This matches how JavaScript handles objects and is the most robust way to handle cross-platform MessagePack serialization.

## 3. Implementation Steps

### 3.0 Dependency Check
- Run `go get golang.org/x/sync` and `go mod tidy` to resolve missing dependencies identified by LSP.

### 3.1 Update Models (`builder/models/models.go`)
- Change `DocLens map[int]int` to `map[string]int`.
- Change `Inverted map[string]map[int][]int` to `map[string]map[string][]int`.

### 3.2 Update Search Generator (`builder/generators/search.go`)
- Import `strconv`.
- Use `strconv.Itoa(i)` when populating `index.DocLens` and `index.Inverted`.
- Ensure strict flushing of the `gzip.Writer` by calling `Close()` explicitly before returning.

### 3.3 Update Search Engine (`builder/search/engine.go`)
- Import `strconv`.
- Update `PerformSearch` to use string keys for `index.DocLens` and `index.Inverted`.
- Update `checkPhraseUnified` to accept a string `postID`.

### 3.4 Update WASM Client (`cmd/search/main.go`)
- Reset the global `index` variable before decoding to ensure a clean state.
- Improve error reporting.

### 3.5 Update Tests
- Fix `builder/search/engine_test.go` and `builder/benchmarks/benchmarks_test.go` to match the new string-keyed map structure.

## 4. Verification Plan
- Run `go test ./...` to ensure no regressions in the builder.
- Perform a manual build and check `search.bin` size.
- Verify search in the browser to ensure the `Decode error` is resolved.
