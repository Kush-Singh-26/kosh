# Plan: Search Relevance & Live Match Fix (v1.3.8)

This plan addresses user feedback regarding missing search results and broken highlighting in Kosh's search engine.

## 1. Problem Analysis

### 1.1 "Not showing all results" (The Live Search Flaw)
Kosh's engine is built for exact and 2-distance fuzzy matching, but it lacks **Prefix Matching**.
If a user is typing "programming" into the live search bar:
- They type "prog".
- The index contains "program" (the stemmed version).
- The Levenshtein distance between "prog" and "program" is 3. Since the max allowed is 2, it filters it out entirely.
- Result: The user sees zero results while typing, making the search feel broken.

Additionally, the engine currently filters out stop words like "how to". If a user searches exactly for "how to", the query becomes empty, and the engine returns 0 results instead of falling back to a title scan.

### 1.2 "Highlighting is not working everytime"
The highlighting logic currently uses `strings.Replacer`. If a user searches for "programming", the stem "program" is passed to the snippet extractor.
- `strings.Replacer` replaces exact matches: `program` -> `<b>program</b>`.
- If the text has "PROGRAMMING", it misses it because of case sensitivity.
- If it has "programming", it outputs `<b>program</b>ming`, which looks ugly.

## 2. Proposed Solutions

### 2.1 Add Prefix Matching
In `FuzzyExpand`, we will add a simple `strings.HasPrefix(idxTerm, term)` check. If a user types "prog", it will instantly match the stem "program", returning immediate live results.

### 2.2 Add Empty Query Fallback
In `PerformSearch`, if BM25 parsing results in an empty `queryTerms` slice but the user typed something (like "how to"), we will fall back to a direct substring scan over post Titles and Descriptions to ensure we always return something relevant.

### 2.3 Regex-Based Full-Word Highlighting
We will replace `strings.Replacer` with `regexp` in `ExtractSnippet`.
- Pattern: `(?i)\b((term1|term2)\w*)\b`
- This matches the entire word (case-insensitive) based on the root stem.
- Replacement: `<b>$1</b>` (preserves exact original casing while highlighting the full word).

## 3. Implementation Steps

1. **`builder/search/engine.go`**:
   - Update `replacerCache` to store `*regexp.Regexp`.
   - Replace `getAllReplacer` with `getHighlightRegex`.
   - Update `ExtractSnippet` to use `re.ReplaceAllString`.
   - Update `PerformSearch` to handle the empty `queryTerms` fallback.

2. **`builder/search/fuzzy.go`**:
   - Update `FuzzyExpand` to check `strings.HasPrefix(idxTerm, term)` alongside the Levenshtein distance check.
