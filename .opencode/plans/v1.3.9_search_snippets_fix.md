# Plan: Restore Full Search Snippets & Relevance (v1.3.9)

## 1. Problem Analysis

The user reported that searching for "word embeddings" behaves poorly:
1. It does not rank the blog post containing the exact phrase as #1.
2. When the correct blog post *is* found, the phrase is not highlighted in the search results snippet.

### Why is the ranking wrong?
When you search for `word embeddings` without quotes, the search engine stems the words and searches for them independently (`word` and `embed`). Because it doesn't treat them as a continuous phrase, a post with the word "word" mentioned 50 times might rank higher than a post that has the exact phrase "word embeddings" once.
**Solution:** We need to add an **Implicit Phrase Boost**. If the user types multiple words, the engine should silently check if they appear as an exact phrase in the text, and if so, give that post a massive ranking boost.

### Why is the highlighting missing?
In Kosh v1.3.1, an aggressive optimization was made: the raw `Content` of the blog posts was removed from the `search.bin` index to shrink the WASM payload size. 
Because the engine no longer has the body of the post, the snippet extractor is forced to scan *only* the `Description` field. If "word embeddings" appears deep in the body of your Positional Encoding blog (but not in the description), the extractor cannot find it to highlight it. It just returns the first 150 characters of the description.
**Solution:** We must revert the removal of `Content` from the search index. Having the full text is absolutely required to generate high-quality, highlighted snippets for words found deep inside a post. 

## 2. Proposed Changes

1. **Restore `Content` to the Index (Models)**
   - Add `Content string` back to `models.PostRecord` and `cache.SearchRecord`.
   - Update `builder/services/post_single.go` and `builder/services/post_parser.go` to pass the parsed plain text into this field.

2. **Restore Snippet Context (Engine)**
   - In `builder/search/engine.go`, change `ExtractSnippet(post.Description, finalHighlightTerms)` back to `ExtractSnippet(post.Content, finalHighlightTerms)`.
   - Update the schema version to `6`.

3. **Implement Implicit Phrase Boost (Engine)**
   - In `PerformSearch`, add a block that evaluates multi-word queries against `checkPhraseUnified`. If they match as a sequence, apply a major score boost so exact phrase matches float to the top of the results.

4. **Rebuild WASM**
   - Recompile the WASM binary to accept the new Schema v6 so the browser can decode the `Content` field.

## 3. Trade-offs
This will increase the size of `search.bin` from ~200KB to perhaps ~400-500KB (gzipped). For a modern WASM application, this is still an instant sub-50ms download, and the UX improvement of having actual working snippets is well worth the bytes.
